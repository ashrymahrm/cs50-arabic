البحث الخطي

  • تعرّفنا الأسبوع الماضي على المصفوفة، وهي عناصر مخزنة في مواضع متجاورة في الذاكرة.

  • تخيّل المصفوفة كصف من سبع خزائن حمراء:

    [0] [1] [2] [3] [4] [5] [6]
  • الموضع في أقصى اليسار هو الفهرس 0، بداية المصفوفة، والموضع في أقصى اليمين هو الفهرس 6، نهايتها.
  • لنفترض أننا نريد معرفة هل العدد 50 موجود في المصفوفة. على الحاسوب فحص الخزائن لمعرفة ذلك. نسمي عملية العثور على عدد أو محرف أو سلسلة أو عنصر آخر «البحث».
  • يمكن تمرير المصفوفة إلى خوارزمية تفحص الخزائن وتعيد true أو false بحسب وجود العدد 50 خلف أحد الأبواب.

  • قد نعطي الخوارزمية التعليمات الآتية:

    For each door from left to right
    If 50 is behind door
        Return true
Return false

    هذه التعليمات شيفرة كاذبة: وصف يستطيع الإنسان قراءته للتعليمات التي قد نعطيها للحاسوب.

  • يمكن لعالم الحاسب صياغة الوصف بصورة أقرب إلى البرمجة:

    For i from 0 to n-1
    If 50 is behind doors[i]
        Return true
Return false

    ما زال هذا الوصف ليس شيفرة فعلية، لكنه قريب من شكلها النهائي.

البحث الثنائي

  • البحث الثنائي خوارزمية أخرى يمكن استخدامها للعثور على العدد 50.

  • إذا كانت القيم داخل الخزائن مرتبة من الأصغر إلى الأكبر، فستكون الشيفرة الكاذبة للبحث الثنائي كما يأتي:

    If no doors left
    Return false
If 50 is behind middle door
    Return true
Else if 50 < middle door
    Search left half
Else if 50 > middle door
    Search right half

  • وباستخدام مفردات أقرب إلى الشيفرة يمكن تعديلها هكذا:

    If no doors left
    Return false
If 50 is behind doors[middle]
    Return true
Else if 50 < doors[middle]
    Search doors[0] through doors[middle - 1]
Else if 50 > doors[middle]
    Search doors[middle + 1] through doors[n - 1]

    من هذا الوصف القريب من الشيفرة، يمكنك تخيّل التنفيذ البرمجي الفعلي.

زمن التنفيذ

ملاحظة تقنية تحريرية: O يعبّر عن حد علوي تقاربي، وΩ عن حد سفلي، وΘ عن حد محكم. ليست هذه الرموز مرادفات تلقائية للأسوأ والأفضل؛ نحدد أولًا دالة الزمن التي نحللها. مثلًا، أفضل حالة للبحث الخطي والثنائي قد تكون Θ(1) إذا كان العنصر في أول موضع مفحوص، بينما أسوأ حالة للبحث الثنائي Θ(log n). كذلك ترتيب القائمة له تكلفة؛ لا نفترض أن ترتيبها أولًا أوفر لعملية بحث واحدة دائمًا.
  • يمكن تحليل الزمن الذي تحتاج إليه الخوارزمية لحل المشكلة.

  • نحلّل زمن التنفيذ باستخدام ترميز Big O. انظر إلى الرسم الآتي:

    رسم يقارن معدلات نمو زمن التنفيذ.
  • بدل وصف الكفاءة بأرقام دقيقة جدًا، يناقش علماء الحاسب معدل نمو أزمنة التنفيذ.
  • في الرسم، الخوارزمية الأولى من الرتبة O(n)، والثانية أيضًا من الرتبة O(n)، لأننا نهمل العوامل الثابتة في Big O. أما الثالثة فمن الرتبة O(log n).

  • يوضح شكل المنحنى كفاءة الخوارزمية. من معدلات النمو الشائعة:

    • O(n²)
    • O(n log n)
    • O(n)
    • O(log n)
    • O(1)
  • من المعدلات السابقة، ينمو O(n²) بأكبر سرعة، بينما O(1) ثابت ولا ينمو مع حجم المدخلات.
  • البحث الخطي من الرتبة O(n)، لأنه قد يحتاج إلى n خطوة في أسوأ حالة.
  • البحث الثنائي من الرتبة O(log n)، لأنه يستبعد في كل خطوة جزءًا كبيرًا من العناصر المتبقية، حتى في أسوأ حالة.
  • يهتم المبرمجون بالحالة الأسوأ وحدها العلوي، وبالحالة الأفضل وحدها السفلي أيضًا.
  • يقدّم المصدر الرمز Ω لوصف حد سفلي، ويربطه هنا بتحليل الحالة الأفضل، مثل Ω(log n). راجع الملاحظة التقنية أدناه للتفريق بين المفهومين.
  • يستخدم المصدر الرمز Θ عندما يتطابق معدل الحدين العلوي والسفلي، ويصفه هنا بتساوي معدلي الحالتين الأفضل والأسوأ. راجع الملاحظة التقنية للتحديد الأدق.
  • الترميز التقاربي يصف نمو تكلفة الخوارزمية كلما كبر حجم المدخلات.
  • ستدرس هذه الموضوعات بتفصيل أوسع مع تقدمك في علوم الحاسب.

البرنامج search.c

  • لتنفيذ البحث الخطي، اكتب code search.c في الطرفية، ثم:

    // Implements linear search for integers

#include <cs50.h>
#include <stdio.h>

int main(void)
{
    // An array of integers
    int numbers[] = {20, 500, 10, 5, 100, 1, 50};

    // Search for number
    int n = get_int("Number: ");
    for (int i = 0; i < 7; i++)
    {
        if (numbers[i] == n)
        {
            printf("Found\n");
            return 0;
        }
    }
    printf("Not found\n");
    return 1;
}

    يتيح التصريح الذي يبدأ بـ int numbers[] تحديد قيم عناصر المصفوفة عند إنشائها. وتنفذ حلقة for البحث الخطي. يعيد return 0 حالة نجاح وينهي البرنامج، بينما يعيد return 1 حالة فشل وينهيه.

  • لقد نفّذنا البحث الخطي بأنفسنا بلغة C!

  • وماذا لو أردنا البحث عن سلسلة نصية في مصفوفة؟ عدّل الشيفرة هكذا:

    // Implements linear search for strings

#include <cs50.h>
#include <stdio.h>
#include <string.h>

int main(void)
{
    // An array of strings
    string strings[] = {"battleship", "boot", "cannon", "iron", "thimble", "top hat"};

    // Search for string
    string s = get_string("String: ");
    for (int i = 0; i < 6; i++)
    {
        if (strcmp(strings[i], s) == 0)
        {
            printf("Found\n");
            return 0;
        }
    }
    printf("Not found\n");
    return 1;
}

    لا نستخدم == لمقارنة محتوى السلاسل هنا. نستخدم strcmp من المكتبة string.h، وهي تعيد 0 عند تطابق السلسلتين. لاحظ أيضًا تثبيت طول المصفوفة في الشيفرة بالقيمة 6، وهو أسلوب أقل قابلية للصيانة.

  • يمر البرنامج على مصفوفة السلاسل للبحث عن السلسلة المطلوبة. إذا ظهر segmentation fault، أي محاولة وصول إلى ذاكرة غير مسموح بها، فتأكد أنك كتبت i < 6 لا i < 7.
  • اقرأ المزيد عن strcmp في صفحات دليل CS50. المصدر المرتبط

البرنامج phonebook.c

  • يمكن جمع فكرتي الأعداد والسلاسل في برنامج واحد. اكتب code phonebook.c في الطرفية، ثم:

    // Implements a phone book without structs

#include <cs50.h>
#include <stdio.h>
#include <string.h>

int main(void)
{
    // Arrays of strings
    string names[] = {"Kelly", "David", "John"};
    string numbers[] = {"+1-617-495-1000", "+1-617-495-1000", "+1-949-468-2750"};

    // Search for name
    string name = get_string("Name: ");
    for (int i = 0; i < 3; i++)
    {
        if (strcmp(names[i], name) == 0)
        {
            printf("Found %s\n", numbers[i]);
            return 0;
        }
    }
    printf("Not found\n");
    return 1;
}

    رقم Kelly يبدأ بـ +1-617، ورقم David يبدأ بـ +1-617، ورقم John يبدأ بـ +1-949. العنصر names[0] هو Kelly، وnumbers[0] رقمها. تتيح هذه الشيفرة البحث عن رقم شخص معين في دليل الهاتف.

  • تعمل الشيفرة، لكن تنظيمها يعرّضنا للأخطاء: فقد لا تتطابق الأسماء مع أرقامها إذا تغير ترتيب إحدى المصفوفتين وحدها. ألن يكون أفضل أن ننشئ نوع بيانات يربط الشخص برقمه؟

البُنى Structs

  • تتيح C إنشاء أنواع بيانات خاصة بنا باستخدام struct.

  • يمكن إنشاء نوع اسمه person يحتوي على name وnumber. تأمل:

    typedef struct
{
    string name;
    string number;
} person;

    يمثل هذا نوعًا جديدًا اسمه person، يحتوي على سلسلة اسمها name وأخرى اسمها number.

  • يمكن تحسين برنامج دليل الهاتف السابق هكذا:

    // Implements a phone book with structs

#include <cs50.h>
#include <stdio.h>
#include <string.h>

typedef struct
{
    string name;
    string number;
} person;

int main(void)
{
    person people[3];

    people[0].name = "Kelly";
    people[0].number = "+1-617-495-1000";

    people[1].name = "David";
    people[1].number = "+1-617-495-1000";

    people[2].name = "John";
    people[2].number = "+1-949-468-2750";

    // Search for name
    string name = get_string("Name: ");
    for (int i = 0; i < 3; i++)
    {
        if (strcmp(people[i].name, name) == 0)
        {
            printf("Found %s\n", people[i].number);
            return 0;
        }
    }
    printf("Not found\n");
    return 1;
}

    تبدأ الشيفرة بـ typedef struct لتعريف النوع person. يحتوي كل عنصر على name وnumber من نوع string. تنشئ main مصفوفة people من النوع person بحجم 3، ثم تسند أسماء الأشخاص الثلاثة وأرقامهم. يتيح استخدام النقطة، مثل people[0].name، الوصول إلى حقل الاسم في الشخص ذي الفهرس 0 وإسناد قيمة إليه.

الترتيب وخوارزمية الاختيار

  • الترتيب هو تحويل قائمة قيم غير مرتبة إلى قائمة مرتبة.
  • قد يجعل ترتيب القائمة البحث فيها أقل تكلفة. تذكّر أن البحث الثنائي يتطلب قائمة مرتبة، ولا يصلح مباشرة لقائمة غير مرتبة.
  • توجد خوارزميات ترتيب كثيرة.
  • إحداها خوارزمية الترتيب بالاختيار، Selection Sort.

  • يمكن تمثيل المصفوفة هكذا:

    Seven red lockers side by side with the last labeled as n-1

    [0] [1] [2] [...] [n-3] [n-2] [n-1]

  • الشيفرة الكاذبة للترتيب بالاختيار هي:

    For i from 0 to n–1
    Find smallest number between numbers[i] and numbers[n-1]
    Swap smallest number with numbers[i]

  • تلخيصًا للخطوات، يحتاج المرور الأول إلى n - 1 مقارنة، والثاني إلى n - 2، وهكذا. يمكن تمثيل المجموع:

    (n - 1) + (n - 2) + (n - 3) + ... + 1
  • يساوي المجموع n(n-1)/2، ومعدل نموه O(n²). في أسوأ حالة يكون الحد العلوي O(n²)، وفي أفضل حالة يظل الحد السفلي Ω(n²).

الترتيب الفقاعي

  • الترتيب الفقاعي، Bubble Sort، يبدّل العناصر المتجاورة مرارًا حتى «تطفو» العناصر الأكبر إلى النهاية.

  • شيفرته الكاذبة هي:

    Repeat n-1 times
    For i from 0 to n–2
        If numbers[i] and numbers[i+1] out of order
            Swap them
    If no swaps
        Quit
  • مع كل مرور يزداد الجزء المرتب من المصفوفة، لذلك لا نحتاج إلا إلى فحص أزواج العناصر التي لم تُحسم مواضعها بعد.

  • يمكن تحليل كلفته كما يأتي:

    • (n - 1) × (n - 1)
    • n² - n - n + 1
    • n² - 2n + 1
    • وبصورة أبسط، O(n²).
  • في أسوأ حالة يكون الزمن O(n²). وفي أفضل حالة يكون Ω(n)، عند استخدام شرط التوقف المبكر الموضح في الشيفرة.
  • يمكن مشاهدة مقارنة مرئية بين هذه الخوارزميات. المصدر المرتبط

الاستدعاء الذاتي

  • كيف نحسّن كفاءة الترتيب؟

  • الاستدعاء الذاتي، Recursion، هو أن تستدعي الدالة نفسها. رأينا ذلك سابقًا في:

    If no doors left
    Return false
If number behind middle door
    Return true
Else if number < middle door
    Search left half
Else if number > middle door
    Search right half

    نستدعي search كل مرة على نسخة أصغر من المشكلة.

  • وبالمثل، ظهر الاستدعاء الذاتي في شيفرة الأسبوع صفر الكاذبة:

    1  Pick up phone book
2  Open to middle of phone book
3  Look at page
4  If person is on page
5      Call person
6  Else if person is earlier in book
7      Open to middle of left half of book
8      Go back to line 3
9  Else if person is later in book
10     Open to middle of right half of book
11     Go back to line 3
12 Else
13     Quit

  • يمكن تبسيط الوصف لإظهار خاصية الاستدعاء الذاتي:

    1  Pick up phone book
2  Open to middle of phone book
3  Look at page
4  If person is on page
5      Call person
6  Else if person is earlier in book
7      Search left half of book
9  Else if person is later in book
10     Search right half of book
12 Else
13     Quit
  • الحالة الأساسية، Base Case، هي الشرط الذي يوقف الاستدعاء الذاتي ويمنعه من الاستمرار بلا نهاية.

  • الحالة التكرارية، Recursive Case، هي الجزء الذي يستدعي الدالة نفسها بمدخلات معدلة تقرّبها من الحالة الأساسية.

  • تذكّر الهرم الذي أردنا بناءه في الأسبوع الأول:

      #
  ##
  ###
  ####

  • اكتب code iteration.c في الطرفية، ثم:

    // Draws a pyramid using iteration

#include <cs50.h>
#include <stdio.h>

void draw(int n);

int main(void)
{
    // Get height of pyramid
    int height = get_int("Height: ");

    // Draw pyramid
    draw(height);
}

void draw(int n)
{
    // Draw pyramid of height n
    for (int i = 0; i < n; i++)
    {
        for (int j = 0; j < i + 1; j++)
        {
            printf("#");
        }
        printf("\n");
    }
}

    يبني هذا البرنامج الهرم باستخدام الحلقات.

  • ولتنفيذه بالاستدعاء الذاتي، اكتب code recursion.c في الطرفية، ثم:

    // Draws a pyramid using recursion

#include <cs50.h>
#include <stdio.h>

void draw(int n);

int main(void)
{
    // Get height of pyramid
    int height = get_int("Height: ");

    // Draw pyramid
    draw(height);
}

void draw(int n)
{
    // If nothing to draw
    if (n <= 0)
    {
        return;
    }

    // Draw pyramid of height n - 1
    draw(n - 1);

    // Draw one more row of width n
    for (int i = 0; i < n; i++)
    {
        printf("#");
    }
    printf("\n");
}

    تمنع الحالة الأساسية استمرار التنفيذ بلا نهاية. ينهي الشرط if (n <= 0) هذا الاستدعاء بعد حل الجزء المطلوب. كل استدعاء للدالة draw يستدعيها بالقيمة n-1. تصل القيمة في النهاية إلى 0، فتعود الدالة، ثم تُستكمل الاستدعاءات السابقة حتى ينتهي البرنامج.

الترتيب بالدمج

  • يمكن استخدام الاستدعاء الذاتي لتنفيذ خوارزمية أكثر كفاءة، وهي الترتيب بالدمج، Merge Sort.

  • شيفرتها الكاذبة قصيرة:

    If only one number
    Quit
Else
    Sort left half of numbers
    Sort right half of numbers
    Merge sorted halves

  • تأمل قائمة الأعداد الآتية:

      6341

  • أولًا تسأل الخوارزمية: هل تحتوي القائمة على عدد واحد فقط؟ الإجابة لا، فتتابع.

      6341

  • ثانيًا تقسّم القائمة عند المنتصف، أو أقرب موضع إليه، ثم ترتّب النصف الأيسر.

      63|41

  • ثالثًا تنظر إلى النصف الأيسر وتسأل: هل هو عدد واحد؟ بما أن الإجابة لا، تقسّمه مرة أخرى.

      6|3

  • رابعًا تسأل مجددًا: هل هو عدد واحد؟ هذه المرة نعم، فتعود إلى المهمة السابقة عند هذه النقطة:

      63|41

  • خامسًا ترتّب أعداد النصف الأيسر.

      36|41

  • نعود الآن إلى موضعنا في الشيفرة الكاذبة بعد ترتيب اليسار. تتكرر خطوات شبيهة بالخطوات 3 إلى 5 للنصف الأيمن، فنحصل على:

      36|14

  • أصبح النصفان مرتبين. تدمجهما الخوارزمية بمقارنة أول عدد في اليسار بأول عدد في اليمين، ووضع الأصغر أولًا، ثم تكرار ذلك حتى تُنقل الأعداد كلها بالترتيب:

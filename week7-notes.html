القراءة باستخدام SELECT

  • تعطي SELECT COUNT(*) FROM favorites WHERE language = 'C'; عدد الصفوف المطابقة للغة C.
  • وتضيف SELECT COUNT(*) FROM favorites WHERE language = 'C' AND problem = 'Hello, World'; شرط المسألة أيضًا. تجمع AND الشرطين.
  • تعطي SELECT language, COUNT(*) FROM favorites GROUP BY language; نتيجة مجمعة تعرض كل لغة وعددها.
  • ترتب SELECT language, COUNT(*) FROM favorites GROUP BY language ORDER BY COUNT(*); النتيجة حسب العدد تصاعديًا.
  • تستخدم SELECT COUNT(*) FROM favorites WHERE language = 'C' AND (problem = 'Hello, World' OR problem = 'Hello, It''s Me'); أقواسًا لتجميع البدائل. تُمثل علامتا اقتباس متتاليتان اقتباسًا واحدًا داخل النص الحرفي في SQL.
  • تبحث SELECT COUNT(*) FROM favorites WHERE language = 'C' AND problem LIKE 'Hello, %'; عن أسماء مسائل تبدأ بالنص Hello, متبوعًا بمسافة. تمثل % سلسلة محارف، وقد تكون فارغة.
  • وللترتيب التنازلي: SELECT language, COUNT(*) FROM favorites GROUP BY language ORDER BY COUNT(*) DESC;.
  • يمكن تسمية عمود النتيجة باسم مستعار: SELECT language, COUNT(*) AS n FROM favorites GROUP BY language ORDER BY n DESC;.
  • ونحدد عدد صفوف الناتج: SELECT language, COUNT(*) AS n FROM favorites GROUP BY language ORDER BY n DESC LIMIT 1;.
  • من الأعراف كتابة كلمات SQL المفتاحية بأحرف كبيرة، وإن لم تكن هذه الصيغة إلزامية هنا.

الإضافة باستخدام INSERT

  • نضيف صفًا باستخدام INSERT INTO table (column...) VALUES(value, ...);.
  • مثلًا: INSERT INTO favorites (language, problem) VALUES ('SQL', 'Fiftyville');.
  • ثم نتحقق باستخدام SELECT * FROM favorites;.

الحذف باستخدام DELETE

  • يحذف DELETE FROM favorites WHERE Timestamp IS NULL; الصفوف التي لا تحتوي قيمة في Timestamp. افحص الشرط قبل الحذف؛ هذه عملية تغيير فعلية عند تنفيذها على قاعدة.

التحديث باستخدام UPDATE

  • تعدّل UPDATE بيانات الصفوف.
  • مثلًا: UPDATE favorites SET language = 'SQL', problem = 'Fiftyville';. لعدم وجود WHERE ستتغير كل الصفوف.
  • لهذه الأوامر أثر كبير. في الأنظمة الفعلية نضبط الصلاحيات ونحتفظ بنسخ احتياطية، ونراجع نطاق أي تعديل قبل تنفيذه.

الربط باستخدام JOIN

  • نريد بيانات من shows وratings، والعلاقة بين id في الأول وshow_id في الثاني.
  • يمكن جمع أعمدة الجداول في نتيجة استعلام باستخدام JOIN.

  • نفذ المثال التالي:

    SELECT * FROM shows
  JOIN ratings ON shows.id = ratings.show_id
  WHERE rating >= 6.0
  LIMIT 10;

    يعرض الناتج أعمدة من الجدولين معًا.

  • بعد علاقة الواحد إلى واحد، ننظر إلى الواحد إلى متعدد باستخدام genres:

    SELECT * FROM genres
LIMIT 10;

    قد يظهر العمل نفسه مع عدة تصنيفات، وهي علاقة واحد إلى متعدد.

  • افحص .schema genres لمعرفة بنية الجدول.

  • ولمعرفة الأعمال الكوميدية:

    SELECT title FROM shows
WHERE id IN (
  SELECT show_id FROM genres
  WHERE genre = 'Comedy'
  LIMIT 10

    تظهر عناوين منها Catweazle.

  • يمكن معرفة مزيد عنه بربط الجداول:

    SELECT * FROM shows
JOIN genres

الفهارس

  • يمكن للفهرس تحسين أداء بعض الاستعلامات على الجداول، بحسب البيانات وخطة التنفيذ.
  • تساعد الفهارس على تجنب فحص صفوف كثيرة في الحالات المناسبة.
  • فعّل قياس الزمن باستخدام .timer on داخل sqlite3.
  • نفذ SELECT * FROM shows WHERE title = 'The Office'; ولاحظ الزمن.
  • ثم أنشئ الفهرس باستخدام CREATE INDEX title_index ON shows (title);.

  • تستخدم SQLite بنية B-tree للفهرسة؛ يمكن لعقدتها أن تتفرع إلى أكثر من طفلين، بخلاف الشجرة الثنائية.

    وصف الشكل: شجرة متعددة الفروع، توضح أن العقدة في B-tree يمكن أن يكون لها أكثر من طفلين.

  • ويمكن إنشاء فهارس أخرى كما يأتي:

    CREATE INDEX name_index ON people (name);
CREATE INDEX person_index ON stars (person_id);

  • أعد تشغيل الاستعلام وقارن الزمن. لا تضمن هذه المقارنة فرقًا ثابتًا؛ قد تؤثر الذاكرة المخبأة وحجم البيانات.

    SELECT title FROM shows WHERE id IN 
    (SELECT show_id FROM stars WHERE person_id = 
        (SELECT id FROM people WHERE name = 'Steve Carell'));
  • الفهارس تستهلك مساحة وتضيف كلفة إلى عمليات الكتابة، لذلك نوازن فائدتها ولا نفهرس كل عمود تلقائيًا.

استخدام SQL في Python

توضيح تقني: نمرر مدخلات البيانات كوسائط منفصلة إلى db.execute، ولا نبني نص الاستعلام بضمها أو إدراجها عبر f-string. أما أسماء الجداول والأعمدة فلا تعامل كقيم قابلة للربط بالطريقة نفسها؛ نختارها من خيارات موثوقة محددة. مرجع التوضيح

  • يمكن استخدام مكتبة CS50 للتعامل مع SQL:

    from cs50 import SQL
  • تختصر المكتبة بعض خطوات تنفيذ SQL من Python.
  • راجع توثيق SQL في مكتبة CS50 المرتبط. المصدر المرتبط
  • لنستخدم Python وSQL معًا.

  • عدّل favorites.py:

    # Searches database for popularity of a problem

from cs50 import SQL

# Open database
db = SQL("sqlite:///favorites.db")

# Prompt user for favorite
favorite = input("Favorite: ")

# Search for title
rows = db.execute("SELECT COUNT(*) AS n FROM favorites WHERE problem = ?", favorite)

# Get first (and only) row
row = rows[0]

# Print popularity
print(row["n"])

    تحدد db = SQL("sqlite:///favorites.db") ملف القاعدة، وتنفذ db.execute الاستعلام مع القيم الممررة. تعيد قراءة SELECT قائمة قواميس؛ في هذا المثال تعيد صف نتيجة واحدًا داخل القائمة. رابط المثال الأصلي مرفق. المصدر المرتبط

حالات التسابق

توضيح تقني: تدير SQLite الكتابة والقفل ضمن نموذجها للعزل. راجع توثيق المعاملات والعزل عند بناء عمليات متزامنة، وقد يلزم التعامل مع انشغال القاعدة أو إعادة المحاولة. مرجع التوضيح
  • قد تظهر مشكلات عند استخدام قاعدة البيانات بصورة متزامنة.
  • تخيّل عدة مستخدمين ينفذون عمليات على القاعدة في الوقت نفسه.
  • قد تتداخل خطوات القراءة والتعديل، فتضيع بعض التحديثات إذا لم يُصمم التزامن بصورة صحيحة.
  • تساعد المعاملات BEGIN TRANSACTION وCOMMIT وROLLBACK على تجميع العمليات وإدارتها. [توضيح: تفادي التسابق يعتمد أيضًا على مستوى العزل والقفل وطريقة كتابة العمليات، لا على إضافة هذه الكلمات وحدها.]

حقن SQL

تنبيه أمني تحريري: مثال المقارنة بكلمة المرور في SQL محفوظ كما ورد للتوضيح فقط، وليس تصميم مصادقة جاهزًا. الأنظمة الحقيقية تخزن مشتقات آمنة لكلمات المرور لا نصها الصريح، وتتحقق منها بأدوات مصادقة مناسبة.
  • تربط علامات ? قيم المدخلات بالاستعلام كمعاملات. من أخطار بناء استعلام بدمج النصوص أن يحاول مدخل خارجي تغيير بنية SQL نفسها؛ يسمى ذلك حقن SQL.

  • تأمل نموذج تسجيل الدخول:

    لقطة نموذج تسجيل الدخول في GitHub محجوبة مؤقتًا لحين حسم حقوق الطرف الثالث. وصف بديل: حقل اسم مستخدم وحقل كلمة مرور وزر دخول. أمثلة SQL أدناه تعليمية وليست نموذج دخول فعليًا في هذا الموقع.

  • المثال التالي يوضح استخدام المعاملات لحماية بنية الاستعلام:

    rows = db.execute("SELECT COUNT(*) FROM users WHERE username = ? AND password = ?", username, password)

    تفصل ? بين نص SQL والقيم المرتبطة به. [تصحيح تحريري: ليست آلية تحقق من صحة اسم المستخدم أو كلمة المرور؛ التحقق من الهوية وصحة المدخلات مسؤوليتان منفصلتان.]

  • لا نتعامل مع مدخلات المستخدم بوصفها تعليمات موثوقة.
  • تُمرر القيم منفصلة إلى db.execute بدل دمجها في نص SQL. [تصحيح تحريري: لا تعتمد الحماية على حذف المحارف التي تبدو ضارة؛ ربط المعاملات يحافظ على تفسيرها كبيانات.]
